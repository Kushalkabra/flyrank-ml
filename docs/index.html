The Content Refresh Signal

Abstract. With a limited editorial team and a growing content inventory, which pages deserve review first? This study builds a client-held-out model that ranks 30,000 pages by predicted decline risk, using only search and engagement signals available before any review decision is made. A Gradient Boosting model reaches Precision@50 of 0.76 against a transparent rule-based baseline's 0.62 — a 23% lift, on the same held-out clients and the same metric. The model leans more heavily on traffic volume and content age than on content-quality signals, a limitation this paper reports rather than hides. The result is a ranked, reason-coded action playbook, not a verdict on any single page.

01 — Introduction

A content team can't review everything, so the ranking has to be honest

A content team managing thousands of pages cannot manually check each one for decline, opportunity, or staleness every sprint. Some prioritization rule is always in use — usually an informal one, based on whichever pages someone happened to notice. This study asks a narrower, answerable question: given a page's trailing 90-day search and engagement signals, can a model rank pages by review priority more precisely than a simple, transparent rule — and if so, by how much, and with what caveats?

The unit of analysis is one content page. The decision this work supports is which pages an editor reviews first this cycle. The action is a manual review and, where warranted, a refresh. The cost of getting it wrong is asymmetric: a false positive wastes editor time on a page that wasn't really at risk, while a false negative lets a genuinely declining, high-demand page go unreviewed for another cycle. That asymmetry is why this study is built and evaluated around Precision@50 — how many of the top 50 ranked pages are actually worth the review — rather than plain accuracy.

02 — Data

30,000 pages, 32 clients, one 90-day snapshot

This study uses the anonymized starter release from the FlyRank ML Internship dataset (content_refresh_anonymized.csv): 30,000 pseudonymized content items across 32 pseudonymized clients, each described by 44 trailing-90-day search and engagement columns. Rows are filtered to pages with impressions_90d > 0 and content_age_days >= 90 — every row in this release already meets that bar.

Deliberately excluded:

  • No raw query, URL, title, or client-identifying text — none ships in this release, and none is reconstructed here.
  • No FlyRank product decision flags (health score, priority score, action type) — the release ships observable signals only.
  • 30-day and previous-30-day breakdown fields are used only to verify the label definition, never as model features.

03 — Methodology

A proxy label, an honest split, and a leakage audit that already caught one mistake

Label. is_declining = trend_direction == "down" — a same-window classification, not a verified future outcome. This proxy is used consistently and its limitation is carried through every section below rather than argued away.

Baseline. A transparent rule: the gap between a page's CTR and its position tier's volume-filtered average CTR, weighted by demand (log impressions), plus a small capped bonus for pages stale 90–180 days. One reason code: ctr_underperform_vs_position.

Model. Gradient Boosting, selected after comparing Logistic Regression (AUC 0.528, barely above chance) and Random Forest (AUC 0.599) on identical features and splits — Gradient Boosting had the clearest edge (AUC 0.614). Ten features, all knowable before the decision point: trailing impressions, clicks, sessions, average position, CTR, content age, days since last update, word count, engagement rate, and scroll rate.

Validation design. Client-grouped 75/25 split (GroupShuffleSplit on client ID), verified zero client overlap between train and test. This choice was not academic: the same model under a plain random row split scored Precision@50 of 0.94, with 31 of 32 clients leaking across train and test. The honest, client-held-out number is 0.76 — the gap is reported in full in Limitations.

Leakage audit. An earlier trap (feeding the literal target-window value in as a "feature") pushed AUC from an honest 0.595 to a meaningless 1.000, demonstrating what leakage looks like before it was ruled out here. The final ten-feature set was re-audited: none is one of the fields the label is directly computed from, and no product flag was used as a feature.

05 — Limitations

What this study does not show

  • Proxy label, not a verified outcome. The label is computed from the same window as the features. A stricter prior-90-days-predicts-next-30-days label was piloted separately (AUC 0.595 on a mid-panel month) and is the honest next iteration, not what's reported above.
  • Small, single-snapshot dataset. 30,000 pages, 32 clients, one time window. Not tested on a different vertical, time period, or client outside this release.
  • Feature importance skews toward volume and age, not content quality. Impressions and content age account for 57% of the model's importance combined; CTR contributes about 5%, engagement rate about 1%. A "high risk" score is partly just "old and/or high-traffic," not a diagnosis of why a page struggles.
  • No causal claim. Nothing here shows a refresh causes recovery — that requires a controlled experiment, not this observational data.
  • No claim about Google's ranking algorithm. Every signal used is an observed outcome, never the mechanism behind it.
  • Validation is honest, not exhaustive. The client-grouped split closed the largest leak found (0.94 → 0.76 Precision@50), but a leakage audit rules out only what it checks for.

06 — Ranked Recommendations

Five archetypes, one action each, always with a human in the loop

Every eligible page is scored by the validated model and assigned to one archetype. This is decision-support for prioritizing review — not an automated action, and not a verdict on any individual page.

  1. 1

    Refresh priority — 9,043 pages

    Model decline probability ≥ 0.6 and impressions ≥ 500. The clearest review candidates: real demand, real modeled risk.

  2. 2

    CTR opportunity — 2,327 pages

    CTR sits below half of its position tier's benchmark, with enough impressions for the gap to be real, not noise.

    review_for_ctr_fixreason: ctr_underperform_vs_position
  3. 3

    Monitor, low demand — 5,715 pages

    High modeled risk, but traffic too small for the risk score to be worth immediate editor time.

    monitor_low_priorityreason: high_risk_low_demand
  4. 4

    Protect — 2,676 pages

    Top-tier position, low modeled decline risk. Distribute and leave alone — editing a stable strong page is a no-go, not an action.

    protect_distributereason: strong_stable_asset
  5. 5

    Monitor, routine — 10,239 pages

    No archetype match. No action needed this cycle — not a judgment that these pages don't matter.

    monitor_routine
What should never be automated: auto-publishing any content change from this score alone; auto-pruning a page for scoring monitor_routine; treating a reason code as a finished diagnosis without checking the underlying numbers; using this to promise a refresh will recover traffic, or to make any claim about Google's algorithm.
